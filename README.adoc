= FTL (Finish The Labs) Ansible Collection

An Ansible collection providing reusable grader and solver roles for automated lab validation and completion.

== Overview

FTL is a collection-based approach to lab grading and solving that:

* Provides pre-built grader roles for common validation scenarios
* Supports solver roles for automated lab completion
* Integrates with AgnosticV catalogs and AgnosticD userinfo
* Works across multiple technologies (OpenShift, Ansible, AAP, RHEL, AI, Virtualization)

== Quick Start

=== Installation on Bastion Host

[source,bash]
----
# 1. Clone FTL repository
git clone https://github.com/rhpds/ftl.git ~/ftl
cd ~/ftl

# 2. Run setup script (creates venv, installs Ansible + dependencies)
./bin/setup_ftl

# 3. Add to PATH
echo 'export PATH="$HOME/ftl/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

# 4. Verify installation
which grade_lab solve_lab
----

=== Testing Production Labs

==== MCP (Model Context Protocol) with OpenShift

**Lab Info:**
- Checkpoints: 35 (6 Module 1 + 9 Module 2 + 11 Module 3 + 9 Module 4)
- Environment: OpenShift multi-user
- Time: 10-15 minutes for solver

**Setup:**
[source,bash]
----
# Set environment variables (from demo.redhat.com)
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="apps.cluster-xxxxx.example.com"
export PASSWORD="<user_password>"  # From demo.redhat.com > Your lab > User tab
----

**Test Module 1 (Lab Setup):**
[source,bash]
----
# Grade Module 1 (should mostly pass - pre-deployed)
grade_lab mcp-with-openshift user1 1

# Expected: PASS 6 checkpoints (OpenShift, LibreChat, MCP servers, Gitea)
----

**Test Full Lab:**
[source,bash]
----
# Solve all modules (automated, 10-15 minutes)
solve_lab mcp-with-openshift user1

# Grade all modules
grade_lab mcp-with-openshift user1

# Expected: PASS all 35 checkpoints
# View report
cat /tmp/grading_dir/grading_report_user1.txt
----

==== Automating RHEL In-Place Upgrades with Ansible

**Lab Info:**
- Checkpoints: 57 (26 Module 1 + 26 Module 2 + 5 Module 3)
- Environment: RHEL bastion + 3 nodes (RHEL 7, 8, 9)
- Time: Module 1 (10 min) + Module 2 (30-60 min for upgrades)

**Setup:**
[source,bash]
----
# Set environment variables (from demo.redhat.com)
export AAP_HOSTNAME="https://controller-xxxxx.apps.example.com"
export AAP_PASSWORD="<common_password>"  # From demo.redhat.com > Your lab > Advanced Settings
export AAP_USERNAME="lab-user"  # Optional

# Test AAP connection (AAP 2.6)
curl -k -u ${AAP_USERNAME}:${AAP_PASSWORD} \
  ${AAP_HOSTNAME}/api/controller/v2/ping/
----

**Test Module 1 (Pre-upgrade Analysis):**
[source,bash]
----
# Grade before solving (should fail - CaC not run)
grade_lab automating-ripu-with-ansible 1
# Expected: FAIL (CaC, lab init, analysis not run)

# Solve Module 1 (automated, 5-10 minutes)
solve_lab automating-ripu-with-ansible 1
# Runs: CaC → Lab Init → Analysis → Pet App Install

# Grade after solving
grade_lab automating-ripu-with-ansible 1
# Expected: PASS all 26 checkpoints

# View report
cat /tmp/grading_dir/grading_report_${USER}_module_01.txt
----

**Test Module 2 (Upgrade Execution):**
[source,bash]
----
# WARNING: Module 2 performs actual RHEL upgrades (30-60 minutes)

# Solve Module 2 (automated, non-interactive)
solve_lab automating-ripu-with-ansible 2
# Upgrades: node1 (7→8), node2 (8→9), node3 (9→10)

# Grade after upgrades complete
grade_lab automating-ripu-with-ansible 2
# Expected: PASS all 26 checkpoints

# View report
cat /tmp/grading_dir/grading_report_${USER}_module_02.txt
----

**Test Full Lab:**
[source,bash]
----
# Grade all completed modules
grade_lab automating-ripu-with-ansible

# Expected: PASS 52 checkpoints (Module 1 + 2), Module 3 skipped
# View full report
cat /tmp/grading_dir/grading_report_${USER}.txt
----

Create a lab directory with grader and solver playbooks:

----
# Create lab structure
./utils/create_new_lab.sh my-lab

# Edit grade_lab.yml to add graders
# Edit solve_lab.yml to add solvers

./utils/test_lab.sh my-lab grade_lab

=== Student Usage

Students invoke grading from lab bastion:

[source,bash]
----
# Set required environment variables (from demo.redhat.com)
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="<cluster_ingress_domain>"
export PASSWORD="<user_password>"  # From demo.redhat.com > Your lab > User tab

# Grade lab progress (pass username as argument)
grade_lab <lab-name> user1

# Solve lab automatically
solve_lab <lab-name> user1
----

== Environment Variables

FTL graders and solvers require certain environment variables to be set. These are displayed in demo.redhat.com when labs are deployed.

=== Required Variables

[cols="1,2,1"]
|===
| Variable | Description | Example

| `OPENSHIFT_CLUSTER_INGRESS_DOMAIN`
| OpenShift cluster ingress domain
| `apps.cluster-kg5jj.dynamic.redhatworkshops.io`

| `PASSWORD`
| User password for service authentication (Gitea, etc.)
| From demo.redhat.com > Your lab > User tab
|===

NOTE: `LAB_USER` is automatically set from the username argument (e.g., `grade_lab <lab-name> user1`). No need to export it manually.

=== AAP-Specific Variables (for AAP labs)

[cols="1,2,1"]
|===
| Variable | Description | Example

| `AAP_HOSTNAME`
| AAP Controller URL
| `https://controller-xxxxx.apps.example.com`

| `AAP_PASSWORD`
| AAP user password
| From demo.redhat.com > Your lab > Advanced Settings

| `AAP_USERNAME`
| AAP username
| `lab-user` (default)
|===

IMPORTANT: FTL supports *AAP 2.6* with the new gateway architecture. All AAP roles use `/api/controller/v2/` endpoints (not the legacy `/api/v2/` paths).

=== Optional Variables

[cols="1,2,1"]
|===
| Variable | Description | Default

| `GUID`
| Lab GUID identifier
| Auto-detected from hostname

| `STUDENT_NAME`
| Student name for reports
| Defaults to `LAB_USER`
|===

=== Setting Environment Variables

When using FTL from a lab bastion, set these before running graders/solvers:

[source,bash]
----
# Set from demo.redhat.com > Your lab > User tab
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="apps.cluster-xxxxx.dynamic.redhatworkshops.io"
export PASSWORD="<user_password>"  # From demo.redhat.com > Your lab > User tab

# Run grader (username argument sets LAB_USER automatically)
grade_lab <lab-name> user1
----

TIP: Values for these variables are displayed in demo.redhat.com when labs are provisioned. For MCP labs, check User tab. For AAP labs, check Advanced Settings.

=== Multi-User Grading

When grading as system:admin for multiple users:

[source,bash]
----
# Set cluster-wide variables once
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="apps.cluster-xxxxx.dynamic.redhatworkshops.io"

# Grade user1 (LAB_USER is set automatically from argument)
export PASSWORD="<user1_password>"  # From demo.redhat.com > Your lab > User tab
grade_lab <lab-name> user1

# Grade user2 (update PASSWORD for each user)
export PASSWORD="<user2_password>"  # From demo.redhat.com > Your lab > User tab
grade_lab <lab-name> user2
----

IMPORTANT: Each user has their own password shown in demo.redhat.com > Your lab > User tab. The PASSWORD must match the user you're grading.

== Container Usage

FTL is available as a container image — no local installation required.

[source,bash]
----
podman run --rm \
    -e OPENSHIFT_USERNAME=user1 \
    -e OPENSHIFT_PASSWORD=secret \
    -e OPENSHIFT_API_URL=https://api.cluster-xxxxx.example.com:6443 \
    -e OPENSHIFT_CLUSTER_INGRESS_DOMAIN=apps.cluster-xxxxx.example.com \
    ghcr.io/rhpds/ftl grade ocp4-getting-started user1
----

Run with `--help` for all options, authentication methods, and examples:

[source,bash]
----
podman run --rm ghcr.io/rhpds/ftl --help
----
