= FTL (Finish The Labs)

Automated grading and solving for Red Hat Demo Platform (RHDP) labs.

image:https://img.shields.io/badge/image-quay.io%2Frhpds%2Fftl-blue[FTL Image, link=https://quay.io/repository/rhpds/ftl]

== Architecture

----
                    ┌─────────────────────────────────────────────┐
                    │              Developer Laptop                │
                    │                                             │
                    │  grade_lab mcp-with-openshift user1 1       │
                    │       │                                      │
                    │       ▼                                      │
                    │  ┌──────────────┐   ansible-playbook?        │
                    │  │  grade_lab   │──────────────────────┐    │
                    │  │  (bash)      │   No → use podman    │    │
                    │  └──────────────┘                      │    │
                    │       │                                 ▼    │
                    │       │              ┌──────────────────────┐│
                    │       │              │ quay.io/rhpds/ftl    ││
                    │       │              │  - ansible-core      ││
                    │       │              │  - kubernetes.core   ││
                    │       │              │  - oc 4.18 client    ││
                    │       │              │  - FTL from GitHub   ││
                    │       │              └──────────────────────┘│
                    └───────┼─────────────────────┼────────────────┘
                            │  ~/.kube/config      │ ansible-playbook
                            ▼                      ▼
                    ┌───────────────┐      ┌──────────────────┐
                    │  Bastion Host │      │  OCP / AAP APIs  │
                    │  (Option B)   │─────▶│  (validation)    │
                    └───────────────┘      └──────────────────┘

Option A: Laptop + podman  →  container  →  cluster API
Option B: Bastion + venv   →  ansible    →  cluster API
----

== Quick Start

[source,bash]
----
# Set credentials (from Showroom / demo.redhat.com → User tab)
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="apps.cluster-xxx.dynamic.redhatworkshops.io"
export PASSWORD="<user-password>"
export LAB_USER="user1"

# Grade
grade_lab <lab-name> user1

# Solve then grade
solve_lab <lab-name> user1
grade_lab <lab-name> user1
----

`grade_lab` and `solve_lab` auto-detect the environment:

* *Bastion host* (ansible-playbook available) → runs directly
* *Laptop* (no ansible-playbook) → runs via `podman` automatically

== Running Modes

=== Option A: From Laptop (via podman)

No SSH needed. Requires `podman` and `oc` CLI installed.

[source,bash]
----
# IMPORTANT: Always log into target cluster first
oc login https://api.cluster-xxx.dynamic.redhatworkshops.io:6443 \
  -u admin -p <admin-password> --insecure-skip-tls-verify=true

# Set credentials
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="apps.cluster-xxx.dynamic.redhatworkshops.io"
export PASSWORD="<user-password>"

# Run — uses quay.io/rhpds/ftl:latest automatically
grade_lab mcp-with-openshift user1 1
solve_lab mcp-with-openshift user1
grade_lab mcp-with-openshift user1
----

IMPORTANT: `oc login` immediately before running. Multiple clusters in `~/.kube/config` will cause the wrong cluster to be used if context is stale.

=== Option B: From Bastion Host

Traditional approach. SSH into the lab bastion, install FTL, run directly.

[source,bash]
----
ssh lab-user@bastion

# Install (first time only)
git clone https://github.com/rhpds/ftl.git ~/ftl
cd ~/ftl && bash bin/setup_ftl
echo 'export PATH="$HOME/ftl/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc

# Set credentials and run
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="apps.cluster-xxx.example.com"
export PASSWORD="<user-password>"
grade_lab mcp-with-openshift user1 1
----

=== FTL Source: GitHub (default) vs Local Repo (development)

By default FTL is cloned from GitHub at container startup.
Use local source when developing grader changes before pushing.

[source,bash]
----
# Default: always pulls latest from GitHub main
grade_lab mcp-with-openshift user1 1

# Development: use local FTL checkout (mount over /ftl in container)
podman run --rm \
  -v ~/.kube/config:/home/runner/.kube/config:ro \
  -v $(pwd):/ftl:ro \
  -e LAB_USER=user1 -e PASSWORD=xxx \
  -e OPENSHIFT_CLUSTER_INGRESS_DOMAIN=apps.cluster-xxx.example.com \
  quay.io/rhpds/ftl:latest grade mcp-with-openshift user1 1
----

== Example Labs

=== MCP with OpenShift (OCP + multi-user + Gitea + LiteMaaS)

[source,bash]
----
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="apps.cluster-xxx.dynamic.redhatworkshops.io"
export PASSWORD="<user-password>"          # from Showroom → User tab
export GITEA_ADMIN_USER="mcpadmin"         # from Showroom ConfigMap
export GITEA_ADMIN_PASSWORD="<gitea-pass>" # from Showroom ConfigMap

grade_lab mcp-with-openshift user1 1      # Module 1: pre-deployed infra check
solve_lab mcp-with-openshift user1        # Solve all modules
grade_lab mcp-with-openshift user1        # Verify: expect SUCCESS 0 Errors
----

See link:labs/mcp-with-openshift/README.md[MCP Lab README] for full details.

=== OpenShift 4 Getting Started (OCP + S2I builds + Tekton)

[source,bash]
----
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="apps.cluster-xxx.dynamic.redhatworkshops.io"
export PASSWORD="<user-password>"

solve_lab ocp4-getting-started user1        # Solve (takes ~10 min — S2I build)
grade_lab ocp4-getting-started user1        # Verify: expect 30/30 SUCCESS
----

NOTE: Module 2 runs an S2I Java build from source (~5-10 min). This is expected.

See link:labs/ocp4-getting-started/README.md[OCP4 Lab README] for full details.

=== Automating RHEL In-Place Upgrades (AAP + no OCP)

[source,bash]
----
export AAP_HOSTNAME="https://controller-xxx.apps.example.com"
export AAP_PASSWORD="<aap-password>"
export AAP_USERNAME="lab-user"

# No oc login needed — AAP lab, not OCP
grade_lab automating-ripu-with-ansible 1   # Grade (expect FAIL — CaC not run)
solve_lab automating-ripu-with-ansible 1   # Solve: runs CaC, Lab Init, Analysis (~15 min)
grade_lab automating-ripu-with-ansible 1   # Verify: expect SUCCESS

# Module 2 performs actual RHEL upgrades (30-60 min)
solve_lab automating-ripu-with-ansible 2
grade_lab automating-ripu-with-ansible 2
----

See link:labs/automating-ripu-with-ansible/README.md[RIPU Lab README] for full details.

== Developer Guide

=== Creating a New Lab

[source,bash]
----
cp -r labs/lab-template labs/my-new-lab
# Edit grade_module_01.yml, solve_module_01.yml
# Test:
grade_lab my-new-lab student 1
----

=== Grader Role Catalog

Every grader role follows the same pattern:

[source,yaml]
----
- ansible.builtin.include_role:
    name: grader_check_<type>
  vars:
    task_description_message: "Exercise 1.1: Pod is running"
    student_error_message: "Pod not found. Check: oc get pods -n {{ project_name }}"
    # role-specific vars...
----

[cols="1,2,2"]
|===
| Role | What it checks | Key vars

| `grader_check_ocp_resource`
| Any K8s resource exists (by name/kind)
| `resource_kind`, `resource_name`, `resource_namespace`

| `grader_check_ocp_pod_running`
| Pod exists and is Running (regex name match)
| `pod_name` (regex), `pod_namespace`, `min_ready_pods`

| `grader_check_ocp_service_exists`
| Service exists with correct port
| `service_name`, `service_namespace`, `check_port`

| `grader_check_ocp_route_exists`
| Route exists (optionally with host match)
| `route_name`, `route_namespace`, `route_host`

| `grader_check_http_endpoint`
| HTTP(S) endpoint returns expected status
| `url`, `expected_status_code`, `validate_certs`

| `grader_check_command_output`
| Shell command output matches expected
| `command`, `expected_output` or `expected_output_regex`

| `grader_check_aap_job_completed`
| AAP job template ran and succeeded
| `job_template_name`, `aap_hostname`, `aap_username`, `aap_password`

| `grader_check_aap_licensed`
| AAP has valid license
| `aap_hostname`, `aap_username`, `aap_password`

| `grader_check_file_exists`
| File exists on managed host
| `file_path`, `host`

| `grader_check_service_running`
| Systemd service is active
| `service_name`, `host`

|===

=== Three-Play Grader Pattern

Every grader module follows this structure:

[source,yaml]
----
# Play 1: Initialize
- name: Initialize FTL Grading Session - Module N
  hosts: localhost
  vars:
    lab_id: "Lab Name - Module N: Title"
    module_number: "01"
    grader_student_report_file: "grading_report_{{ lookup('env', 'LAB_USER') }}_module_01.txt"
  roles:
    - ftl_run_init

# Play 2: Grade
- name: Grade Module N
  hosts: localhost
  vars:
    grader_student_report_file: "grading_report_{{ lookup('env', 'LAB_USER') }}_module_01.txt"
  tasks:
    - ansible.builtin.include_role:
        name: grader_check_ocp_pod_running
      vars:
        task_description_message: "Exercise 1.1: Pod running"
        pod_name: "myapp-.*"
        pod_namespace: "myproject"
        student_error_message: "Pod not found. Deploy: oc new-app ..."

# Play 3: Finalize
- name: Finalize FTL Grading Session - Module N
  hosts: localhost
  vars:
    module_number: "01"
    grader_student_report_file: "grading_report_{{ lookup('env', 'LAB_USER') }}_module_01.txt"
  roles:
    - ftl_run_grade_report_generation
    - ftl_run_finish
----

=== Rules for Graders

* Use `kubernetes.core.k8s_info` — never `oc` CLI (crashes on arm64 under amd64 emulation)
* Use `failed_when: false` on check tasks so grading continues past failures
* Always set `grader_student_report_file` in EVERY play (init, grade, finalize)
* Exercise numbering: `X.Y` format (module.checkpoint)
* Error messages must tell students the exact command to fix the issue

=== Rules for Solvers

* Use `kubernetes.core.k8s` — never `oc` CLI for resource creation
* Full Deployment spec required on creation (selector + labels + image) — partial strategic-merge fails if object doesn't exist
* For S2I: create ImageStream BEFORE BuildConfig (prevents `InvalidOutputReference`)
* Use `failed_when: false` on optional steps
* Use `retries` + `until` for waiting on builds/deployments (not `wait_for`)

== Container Image

[source,bash]
----
# Build
podman build --platform linux/amd64 -t quay.io/rhpds/ftl:latest -f Containerfile .

# Push (requires quay.io/rhpds push access)
podman push quay.io/rhpds/ftl:latest
----

The image is UBI9-based (linux/amd64) and contains:
`ansible-core` + `kubernetes.core` + `community.general` + `oc` 4.18 client.
FTL labs are cloned from `https://github.com/rhpds/ftl` at container startup.
