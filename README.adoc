= FTL (Finish The Labs)

Automated grading and solving for Red Hat Demo Platform (RHDP) labs.
FTL validates that students have completed lab exercises and can automatically solve them for testing.

image:https://img.shields.io/badge/image-quay.io%2Frhpds%2Fftl-blue[FTL Image, link=https://quay.io/repository/rhpds/ftl]

== Overview

FTL provides:

* *Grader playbooks* — validate student exercises, produce PASS/FAIL reports
* *Solver playbooks* — automatically complete exercises for testing
* *Container image* — `quay.io/rhpds/ftl:latest` with all dependencies built in
* *Run script* — one command from laptop, discovers everything automatically

== Running Graders

There are two ways to run FTL graders:

* *Option A (Recommended): Container from laptop* — no SSH needed, reads cluster state directly
* *Option B: From bastion* — traditional approach, SSH to bastion and run `grade_lab`

=== Option A: Container from Laptop

Uses `quay.io/rhpds/ftl:latest` running via podman on your laptop.
Reads credentials automatically from the Showroom ConfigMap — no manual env var setup.

*Requirements:* `podman` and `oc` installed on your laptop.

[source,bash]
----
# Run interactively — script asks what to grade
./bin/run-grade.sh <lab> <api-url> <admin-password>

# Example — MCP lab
./bin/run-grade.sh mcp-with-openshift \
  https://api.cluster-xxxxx.dynamic.redhatworkshops.io:6443 \
  <admin-password>
----

The script presents an interactive menu:

----
What do you want to grade?
  1. Single user, single module
  2. Single user, all modules
  3. All users, single module  (load test)
  4. All users, all modules    (full load test)
----

*The script automatically:*

1. Logs into the cluster as admin
2. Discovers all lab users from showroom namespaces
3. Reads each user's password from the Showroom ConfigMap
4. Reads Gitea admin credentials from the Showroom ConfigMap
5. Runs the grader container for each user/module combination
6. Shows PASS/FAIL summary

*To use your local FTL repo* (for development — picks up uncommitted changes):
[source,bash]
----
./bin/run-grade.sh mcp-with-openshift \
  https://api.cluster-xxxxx.dynamic.redhatworkshops.io:6443 \
  <admin-password> \
  --local
----

=== Option B: From Bastion (Traditional)

SSH to the lab bastion, set environment variables, run `grade_lab`.

[source,bash]
----
ssh lab-user@bastion

# Clone FTL
git clone https://github.com/rhpds/ftl.git ~/ftl
cd ~/ftl
./bin/setup_ftl

# Add to PATH
echo 'export PATH="$HOME/ftl/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
----

*Set environment variables* (from demo.redhat.com → Your lab → User tab / Advanced Settings):
[source,bash]
----
export OPENSHIFT_CLUSTER_INGRESS_DOMAIN="apps.cluster-xxxxx.dynamic.redhatworkshops.io"
export PASSWORD="<user-password>"
----

*Run grader or solver:*
[source,bash]
----
# Grade a specific module
grade_lab <lab-name> user1 1

# Grade all modules
grade_lab <lab-name> user1

# Solve a specific module
solve_lab <lab-name> user1 1

# Solve all modules
solve_lab <lab-name> user1
----

== Container Image

The FTL container image contains all runtime dependencies.
FTL playbooks are cloned from GitHub at runtime — no image rebuild needed when graders change.

[source,bash]
----
# Build (maintainers only)
podman build --platform linux/amd64 -t quay.io/rhpds/ftl:latest -f Containerfile .
podman push quay.io/rhpds/ftl:latest
----

*What's in the image:*
* UBI9 base (linux/amd64)
* `oc` 4.18 client
* `ansible-core`, `kubernetes`, `openshift` Python packages
* `kubernetes.core` and `community.general` Ansible collections
* `ftl-entrypoint.sh` — clones FTL at startup, then runs `ansible-playbook`

*Override with local repo:*
[source,bash]
----
# --local flag mounts your local FTL repo into the container
./bin/run-grade.sh <lab> <api-url> <password> --local
----

== Credential Notes

=== OCP / App Password

FTL Option A reads the password automatically from the Showroom ConfigMap.
Option B: get it from demo.redhat.com → Your lab → User tab.

=== Gitea Admin Token

When checking Gitea repos, FTL uses the Gitea admin token (not student credentials).
This ensures checks work even if the student hasn't logged into Gitea yet.

The token is read automatically from the Showroom ConfigMap fields:
`gitea_admin_username` and `gitea_admin_password`.

=== SSO Clusters

On clusters using RHSSO/Keycloak, students cannot `oc login` with username/password.
FTL uses admin kubeconfig for all cluster checks — no student login required.

== Creating New Labs

[source,bash]
----
# Use the lab template
cp -r labs/lab-template labs/my-new-lab

# Edit the grader and solver playbooks
vim labs/my-new-lab/grade_module_01.yml
vim labs/my-new-lab/solve_module_01.yml

# Test with container
./bin/run-grade.sh my-new-lab \
  https://api.cluster-xxxxx.dynamic.redhatworkshops.io:6443 \
  <admin-password> \
  --local
----

See link:docs/LAB_AUTHOR_GUIDE.adoc[Lab Author Guide] for grader role reference.
